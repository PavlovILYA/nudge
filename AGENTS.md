# Project rules

- Prefer simple, idiomatic Swift and SwiftUI. Avoid unnecessary abstraction layers and dependencies.
- Use feature branches and focused pull requests; never merge without explicit authorization.
- Never commit secrets, signing certificates, or provisioning profiles.
- Validate changes with GitHub Actions; local Xcode may not support the required SDK.
- Keep commits and PRs focused. Do not implement future features prematurely.
- Explain iOS-specific decisions when they may be unfamiliar to an experienced Java developer.
