# Nudge

**0.5.0 (6)** — задачи с необязательным настойчивым системным будильником. iPhone, iOS 26+, bundle ID `com.pavlovilya.nudge`.

Основная сущность — задача. Она может быть без даты и без будильника. Выполненные задачи сохраняются.

## Задачи

Один список **Задачи**: название, необязательный срок, галочка выполнения и компактная кнопка будильника. Нажатие на текст открывает редактор. Видимый переключатель **Активные / Выполненные** находится над списком. Настройки открываются кнопкой шестерёнки; отдельных разделов будильников и истории нет.

- **Готово** завершает одноразовую задачу и отменяет её сигнал. У повторяющейся сохраняет текущее выполнение и ставит следующее. **Завершить серию** в редакторе окончательно прекращает повторения. Задача остаётся в базе.
- Кнопка будильника включает или отключает сигнал. Если времени нет либо оно прошло, открывается редактор с выбором будущего времени.
- **Изменить время** меняет срок задачи и обновляет связанное событие Calendar.
- **Удалить** — отдельное действие. Завершённые задачи не удаляются автоматически.

Ошибки регистрации/отмены видны при возникновении проблемы. Отсутствие записи AlarmKit само по себе не доказывает завершение задачи.

## Системный экран AlarmKit

**Утверждённая семантика: системный Stop завершает задачу.** Background `CompleteTaskIntent` сохраняет выполнение через SwiftData, затем отменяет сигнал и очищает отложенные срабатывания. Существующее событие Calendar сохраняется. Повторный вызов безопасен. Если отмена не удалась, выполнение остаётся сохранённым, а отмена повторяется при открытии приложения.

Дополнительная кнопка **Действия** запускает отдельный foreground `ChooseTimeIntent`. Она только открывает действия нужной задачи и не завершает её:

- **Отложить** на 5/10/15/30/60 минут, выбранный интервал 1–1440 минут либо произвольные дату и время. Произвольный интервал задаётся Stepper и применяется отдельной кнопкой, а не при каждом изменении значения. Меняется следующий AlarmKit-сигнал, а исходный срок и Calendar event остаются прежними.
- **Отключить будильник** прекращает сигнал и отменяет будущий. Задача остаётся активной; включить будильник можно позднее.

В обычных строках нет Snooze для незвонящего сигнала. Система управляет подписью Stop на современных iOS и может показать дополнительное действие как Open. Приложение не переназначает аппаратные кнопки. Если аппаратное действие вызывает stopIntent, оно тоже завершает задачу.

После обновления откройте Nudge: существующие реально зарегистрированные будущие сигналы получают новые intents с прежними ID и временем. Отсутствующие/отключённые сигналы не восстанавливаются. Уже звонящий старый сигнал не переписывается: его старый Stop может не иметь нового intent; такую задачу завершите в Nudge. Физическое поведение новых действий нужно проверить на iPhone.

## Голосовое создание

Открыть можно кнопкой микрофона, Home Screen widget, Lock Screen widget, Quick Action и `nudge://voice`. Виджет сам не записывает звук; разблокировка выполняется обычным способом.

Произнесите фразу целиком, с паузами → **Остановить запись** → проверьте название/дату/будильник/повторение → **Создать**.

Полный запрос находится в одном многострочном редактируемом поле. После Stop его можно исправить с клавиатуры; кнопка **Дополнить голосом** добавляет новую диктовку к сохранённому тексту, включая ручные правки. Очистка требует отдельного подтверждения. Исходный запрос не заменяется очищенным названием задачи.

Используется **только DictationTranscriber**, preset `progressiveLongDictation`, через SpeechAnalyzer. Результаты собираются по аудиоинтервалам и временным меткам слов. Изменяется соответствующая гипотеза, финализированные части сохраняются. После Stop закрывается микрофон, дочитываются входной поток и финальные результаты. **Фиксированного тайм-аута записи нет**; пауза не останавливает запись. При системном прерывании сохраняется доступный текст. SF/SpeechTranscriber fallback удалён.

Распознавание выполняется на устройстве, аудио не сохраняется и не отправляется на сервер. Если русские ресурсы DictationTranscriber недоступны, остаётся ручной ввод. Установка, проверка и статус **системных ресурсов Apple** находятся в настройках, без сброса ввода. Установленный ресурс повторно не скачивается. Доступность и фактическую работу без интернета нужно проверить на целевом устройстве.

Без распознанной даты можно создать задачу без будильника. При включении сигнала требуется корректное будущее время. Звук и Calendar доступны в необязательном раскрываемом блоке. Интерпретация запускается после записи либо с задержкой после ручной правки; промежуточная речь её не перезапускает. Создание требует подтверждения и защищено от двойного нажатия.

`ReminderInterpreter` возвращает `ReminderDraft`: исходную фразу, название, необязательную дату, флаг сигнала, типизированное правило повторения и предупреждения. Rule-based реализация сохранена; повторения выбираются вручную. LLM в этом PR нет.

## Повторяющиеся задачи

Повторение задаётся при ручном создании, голосовом подтверждении и редактировании: **не повторять / ежедневно / еженедельно / ежемесячно / настроить**. В настройке доступны N часов, N дней, N недель, выбранные дни недели, N месяцев и конкретное число месяца.

- Один Reminder хранит исходный срок, правило, ближайшее выполнение и историю завершений. UUID задачи и alarmID сохраняются.
- Каждый час/N часов — прошедший временной интервал. Дни, недели и месяцы — Calendar в часовом поясе правила, с исходным локальным временем. При переезде правило сохраняет свой часовой пояс.
- Несуществующее время при весеннем DST переносится на ближайшее существующее; при осеннем повторении берётся первое вхождение. 31-е число пропускает месяцы без 31-го. Нет молчаливого переноса на конец месяца.
- **Одновременно ожидает одно выполнение.** Следующее рассчитывается после «Готово»/системного Stop, строго после текущего срока и времени завершения; пропущенные периоды не создают очередь задач. У каждого выполнения новый токен, повторный Stop прежнего токена ничего не пропускает.
- При включённом будильнике следующий фиксированный AlarmKit-сигнал регистрируется из обработчика выполнения, в том числе background LiveActivityIntent. Ошибка регистрации не откатывает уже сохранённое выполнение: задача показывает необходимость повтора, открытие Nudge восстанавливает будущее планирование.
- **Это не автономная бесконечная цепочка сигналов.** Без завершения текущей задачи новые сигналы не появляются. iOS не гарантирует произвольный запуск приложения в фоне. Нативное AlarmKit weekly исследовано, но для согласованной истории и токенов выполнения MVP использует одно фиксированное срабатывание для всех правил. Ограничения, восстановление и физические проверки: [MVP и повторения](docs/mvp-recurrence-qa.md).

Отключение будильника сохраняет правило; «Отложить» меняет только ближайший сигнал, не следующее выполнение серии и не Calendar.

## Звук и Calendar

Для профиля без сохранённого выбора общий звук новых задач — `experimentalVibrationOnly`, бесшумный CAF. Это **не гарантированный системный режим вибрации**: конкретные устройства и настройки могут вести себя иначе. Явный выбор пользователя и звук старых задач не перезаписываются. Ручное, голосовое и общее создание через ReminderStore используют одну политику. Системная мелодия и два оригинальных CAF остаются доступны; Preview не создаёт будильник.

Calendar синхронизируется только **Nudge → Apple Calendar**. Разрешение запрашивается в настройках по действию пользователя. У события название задачи, её исходный срок, длительность 15 минут, ссылка `nudge://reminder/<UUID>` и нет дополнительных календарных уведомлений.

Без даты событие пока не создаётся. Если у связанной задачи убрать дату, старое событие сохраняется до нового срока или явного удаления. Отключение будильника и завершение не удаляют событие. Snooze его не переносит. Для дней/недель/дней недели/месяцев событие получает EKRecurrenceRule. Для почасовых интервалов Calendar показывает только исходное событие с пояснением, без скрытых копий. Завершение серии ограничивает будущие календарные повторы и сохраняет историю. Ошибка Calendar не удаляет задачу и не отменяет её работающий сигнал.

## Хранение и обновление

SwiftData остаётся источником истины. `scheduledAt` стал опциональным; сохранён опциональный `alarmActionsVersion` для обновления системных действий. Новые данные повторения (`recurrenceData`, `nextOccurrenceAt`, `occurrenceID`, `completedOccurrencesData`) и журнал регистрации `alarmWriteStarted` опциональны; старые задачи остаются одноразовыми. UUID, alarmID, выполнение, звук, отложенное время и EventKit-ссылки сохраняются. Путь хранилища не меняется. App и LiveActivityIntent используют один cached ModelContainer/mainContext в процессе приложения; App Groups не добавлялись.

Изменения рассчитаны на автоматическую lightweight migration. Тесты открывают старые хранилища и проверяют прежние поля. При ошибке открытия приложение показывает ошибку, **не удаляет и не пересоздаёт базу**. Не удаляйте Nudge для установки обновления.

## Сборка и установка

Современный Xcode доступен через [GitHub Actions](https://github.com/PavlovILYA/nudge/actions/workflows/ios-build.yml): Release Simulator, Release Device без подписи и unit-тесты. Версия **0.5.0**, build **6**. PR #6 не сливать без проверки на iPhone и явного разрешения.

Артефакты: `Nudge-0.5.0-iOS-Simulator`, `Nudge-0.5.0-iOS-Device-Unsigned` (app ZIP и `Nudge-0.5.0-6-Unsigned.ipa`), `Nudge-TestResults`, `Apple-SDK-Reference`.

IPA устанавливается через Sideloadly поверх приложения с тем же Apple ID/эффективным bundle ID. Не удаляйте приложение: это удалит локальные данные. Номер сборки не менялся, поэтому выбирайте IPA по commit SHA. Widget Extension должен быть подписан вместе с приложением; успешная unsigned сборка не доказывает установку с бесплатным Apple ID. Сертификатов и Apple ID в репозитории нет.

[Актуальный manual QA MVP, повторений и план PR #7](docs/mvp-recurrence-qa.md). Эта итерация ещё не проверена установкой на физический iPhone. [Предыдущая проверка модели задач](docs/task-first-qa.md) сохранена как исторический материал.
