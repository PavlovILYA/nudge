# Nudge 0.5.0 (6): финализация MVP в PR #6

Этот документ описывает текущий код, а не подтверждение физических тестов. Устройство для приёмки: iPhone 13 / iOS 27.2.1. Версия, Bundle ID, default store, Widgets, звук старых задач и EventKit-ссылки не менялись. PR #6 не мёрджить до проверки.

## Принятые ограничения и Apple API

[Speech DictationTranscriber](https://developer.apple.com/documentation/speech/dictationtranscriber) с `progressiveLongDictation`, `.audioTimeRange` и SpeechAnalyzer — единственный движок. Доступность ru-RU и установленных ресурсов проверяется через supportedLocale/AssetInventory. Вход микрофона копируется с отдельным владением; до AnalyzerInput он конвертируется в signed Int16 PCM. Результаты по аудиоинтервалам заменяют гипотезу только соответствующего незавершённого участка. Stop закрывает микрофон, дочитывает поток и вызывает finalizeAndFinishThroughEndOfInput; отмена и системное прерывание сохраняют уже полученный текст. Фиксированного тайм-аута и резервного SFSpeechRecognizer нет.

Полный запрос хранится в памяти; единственное видимое поле является названием при Create. Отдельный очищенный парсером title не редактируется и не используется при сохранении. sourceText/title в ReminderDraft остаются отдельными типизированными параметрами для будущего интерпретатора. Отдельная аудиосессия может менять лишь свою гипотезу. Завершение сессии фиксирует текст; ручная правка инвалидирует её токен. Дополнительная диктовка добавляет слова к исправленному запросу. Интерпретация не работает на каждом partial result. Аудио/полные фразы не пишутся в файлы или OSLog.

[AlarmKit scheduling](https://developer.apple.com/documentation/alarmkit/scheduling-an-alarm-with-alarmkit) и [WWDC25](https://developer.apple.com/videos/play/wwdc2025/230/) различают fixed и relative schedules. SDK 27.2: `Alarm.Schedule.Relative.Recurrence` предоставляет `.never` и `.weekly([Locale.Weekday])`, но не N минут/часов/дней/месяцев. Нативное weekly не используется в MVP: оно живёт независимо от завершения задачи и не выдаёт приложению новый токен экземпляра. Выбран один фиксированный сигнал на ожидающее выполнение, без фонового polling и без очереди сотен будущих сигналов.

Системный Stop завершает текущее выполнение. Background LiveActivityIntent сохраняет историю, следующий срок и новый токен до AlarmKit. Повторный старый intent — no-op. Actions — отдельный foreground intent, не выполняющий задачу. Подпись Stop контролирует система; Actions может выглядеть как Open. Разблокировка и защищённое хранилище остаются под контролем iOS.

**Не обещаем автономные повторения при пропущенном выполнении.** Если пользователь не завершил текущее выполнение системным Stop, остаётся одна просроченная задача. После Stop пропущенные периоды перескакиваются к первому будущему сроку. Если iOS не запустила intent или регистрация не удалась, необходим запуск Nudge и повтор операции. Гарантии произвольного фонового выполнения, работы до первого unlock после reboot и бесконечного числа системных будильников нет. Ошибки системной ёмкости показываются как ошибки регистрации. Запланированный сигнал доставляет AlarmKit, экран приложения для этого не нужен; reboot и закрытое приложение проверяются физически.

[EventKit recurrence](https://developer.apple.com/documentation/eventkit/creating-a-recurring-event) использует EKRecurrenceRule для дней, недель и месяцев, включая выбранные дни недели и число месяца. Поминутной и почасовой частоты у EKRecurrenceFrequency нет: Calendar получает только исходное 15-минутное событие с пояснением. Не создаём скрытый набор копий. События не получают дополнительные Calendar alarms. Обновляем/удаляем только подтверждённое URL+marker событие, неоднозначное совпадение — ошибка, а не создание дубля. Для серии работа ведётся от исходного события с `.futureEvents`. При завершении серии выставляется recurrence end; прошлые события сохраняются. Если завершить серию до её первого срока, исходное событие остаётся, но следующих календарных повторов нет — как и при выполнении будущей одноразовой задачи. Фактическое поведение провайдеров Calendar требует проверки.

## Состояние и восстановление

- `scheduledAt` — исходный якорь; Snooze и очередное Done его не меняют. `recurrenceData` — Codable правило со стабильными unit ID и timezone. `nextOccurrenceAt` — ближайшее выполнение; `occurrenceID` — токен идемпотентности; `completedOccurrencesData` — журнал dueAt/completedAt текущей серии.
- Все новые поля опциональны. Старые одноразовые записи получают nil, UUID/alarmID/звук/Calendar/выполнение/отложение сохраняются. Контейнер и путь прежние, удаление базы при ошибке запрещено. Disk migration fixtures проверяются в CI.
- `alarmDisabled` — намерение пользователя. `alarmNeedsUpdate` для активной задачи — незавершённое планирование, для выключенной/выполненной — незавершённая отмена. Выключение не удаляет правило или событие.
- Сначала сохраняется pending date и сбрасывается `alarmWriteStarted`, затем отменяется старый сигнал. После успешной отмены признак начала новой записи сохраняется до schedule. Только он позволяет принять совпавшую дату после неопределённой ошибки schedule. Старый сигнал той же даты с прежним токеном не считается успешно обновлённым.
- Записи одного alarmID сериализуются до post-await проверок. Изменившиеся completion/disabled/occurrenceID исключают позднее воскрешение старого сигнала. Неудачная отмена сохраняет маркер повтора.
- Системный Stop серии сначала сохраняет факт выполнения и новый токен; при ошибке следующего сигнала выполнение не теряется. При открытии приложения восстанавливается только сохранённое намерение с будущим сроком. Просроченный pending не создаёт сигнал самопроизвольно: пользователь выбирает новое время либо выполняет задачу.
- Галочка, Done и «Завершить серию» в Nudge сохраняют completedAt, отключение и Calendar dirty до внешних операций. Calendar-ошибка не откатывает задачу или AlarmKit; refreshCalendar повторяет ограничение серии.
- Единый MainActor контейнер переиспользуется приложением и intent в процессе. SwiftData/AlarmKit/EventKit не атомарны: ошибка диска или прерывание между операциями требуют reconciliation и могут временно оставить сигнал/событие.

## Проверка на iPhone 13

Установить IPA текущего SHA поверх существующей версии через тот же Apple ID/эффективный Bundle ID, **не удаляя Nudge**. CI unsigned сборка не подтверждает подпись вложенного Widget Extension через Sideloadly.

1. До обновления записать несколько названий, сроков, звуков, Snooze, выполненных задач и Calendar-ссылок. После установки проверить их сохранность. Старые задачи не должны внезапно стать повторяющимися.
2. Проверить видимый переключатель Активные/Выполненные, галочку в строке, редактор и кнопку настроек; выключенный будильник не выглядит запланированным.
3. В Settings проверить статус русских ресурсов, установку отсутствующих, повторную проверку уже установленных. Текст в голосовом экране не теряется после возврата; установка не запускает запись.
4. Голосом произнести «Напомни завтра в восемь вечера забрать посылку», пауза более 30 секунд, затем «а после этого позвонить маме». Запись продолжается; Stop сохраняет обе части. Проверить без интернета.
5. Исправить текст с клавиатуры, дополнить диктовкой с паузами. Правки и прежние фразы остаются, новая гипотеза уточняет только добавление. Очистка — явное действие. После прерывания звонком/фоном доступный текст остаётся, микрофон освобождён; повторный старт без двойного захвата.
6. Без речи сразу ввести текст, создать задачу без даты/сигнала. Проверить название из единственного поля, будущую дату, включение будильника, ручное повторение. Корректная показанная дата активирует Create без изменения минуты. Двойной Create не создаёт копию.
7. Home Screen/Lock Screen widgets, Face ID, Quick Action, холодный/повторный `nudge://voice`: один экран, один микрофон, незавершённые правки не теряются без подтверждения.
8. Одноразовый сигнал через 2 минуты: заблокировать экран, Stop → задача в выполненных, сигнал отменён, Calendar сохранён. Повторить после закрытия Nudge.
9. Второй сигнал: Actions → задача остаётся активной. Быстрые 5/10/15/30/60; затем 7/23/45/90 минут Stepper + подтверждение; затем произвольная дата. Исходный срок/правило/Calendar не меняются. Actions → Отключить: задача активна, сигнал не возвращается при открытии приложения.
10. Серия N часов с ближайшим сроком через 2 минуты: Stop выполняет только текущий экземпляр, сохраняет историю, следующий срок/сигнал появился. Повторный старый intent не должен пропустить период. Пропустить один сигнал: новые сигналы не возникают до Stop, затем один будущий срок без «догоняющих» дублей.
11. Создать ежедневную, каждые 3 дня, каждые 2 недели, вторник/четверг, ежемесячную и 5-го числа. Сверить следующий срок после системного Stop. Проверить 31-е: месяц без числа пропускается. Смена timezone устройства не меняет сохранённую зону правила; DST отдельно моделируется unit-тестами.
12. Отключить будильник серии, снова включить с будущим сроком. Правило/история сохраняются; максимум один сигнал задачи. «Завершить серию» убирает её из активных и отменяет будущий сигнал.
13. Calendar: событие одно, дни/недели/месяцы имеют правильное правило, поминутная/почасовая задача только исходное событие с пояснением. Название/исходный срок обновляются, Snooze и системный Stop отдельного экземпляра не передвигают серию. «Завершить серию» ограничивает её, не удаляя прошлое.
14. Отозвать Calendar permission: задача и AlarmKit сохраняются, доступен retry без дублей. Перемещение/удаление события не приводит к изменению чужого события. Ошибка регистрации AlarmKit после системного Stop сохраняет историю и показывает проблему; после разрешения/повтора создаётся один сигнал.
15. Проверить запланированный сигнал после закрытия Nudge и reboot/первого unlock. Отдельно записать поведение Stop/Actions/Face ID. Галочка/Done в Nudge завершают всю серию; актуальные точечные проверки — [финальные исправления](pr6-final-fixes-qa.md). Проверить русскую/английскую локаль, Dynamic Type, VoiceOver, светлую/тёмную темы и экспериментальный silent CAF. Не считать поведение одного iPhone гарантией на всех устройствах.

При сбое: iOS Settings → Privacy & Security → Analytics & Improvements → Analytics Data → Nudge*.ips. Не публиковать личную транскрипцию. Диагностика OSLog содержит стадии/время/backend/коды ошибок без речи.

## PR #7: локальная LLM

Добавить одну реализацию LocalLLMInterpreter существующего Sendable протокола. Вход — полный sourceText и InterpretationContext; выход — ReminderDraft с title/date/alarmEnabled/RecurrenceRule/warnings. Не менять Speech/UI/ReminderStore ради модели. Валидация типизированных параметров и подтверждение пользователя остаются обязательными. До интеграции отдельно выбрать модель/лицензию, ресурсы iPhone 13, офлайн-установку, отмену/память/замеры и тестовый набор русских неоднозначных запросов. Веса, runtime, загрузки и LLM в PR #6 не добавлены.
