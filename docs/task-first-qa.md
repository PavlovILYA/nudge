# Задача — основной объект: проверка на iPhone 13

Цель: iPhone 13 / iOS 27.2.1. Новые сценарии ниже ещё не проверены на устройстве.

## Короткий manual QA

1. Установить новый IPA поверх текущего Nudge с тем же Apple ID, не удаляя приложение. Сверить старые задачи, UUID/связи, выполненные записи, звуки, исходные сроки и Snooze. Первый раз открыть Nudge для миграции и обновления будущих регистраций AlarmKit.
2. Создать задачу только с названием. Дата отсутствует, будильник выключен, запросов разрешения AlarmKit нет. Перезапуск сохраняет задачу.
3. Добавить дату без будильника, затем включить его. Если даты нет/она прошла, выбрать будущее время в редакторе. Уже показанное корректное время позволяет сохранить без изменения минуты.
4. Проверить единственный список **Задачи**, галочку в строке, кнопку будильника и фильтр **Выполненные**. Галочка отменяет сигнал и сохраняет задачу в выполненных. Удаление — отдельное действие.
5. Запланировать сигнал через две минуты, заблокировать iPhone. Дождаться AlarmKit и нажать системный Stop. Открыть Nudge: задача выполнена, отложений/активного сигнала нет, Calendar event сохранён. Повторить при выгруженном Nudge.
6. Отдельно проверить физические кнопки и системный крестик. Если iOS вызывает stopIntent, ожидается завершение. Не ожидать разных пользовательских команд от Volume/Side; записать фактический результат.
7. На другом сигнале нажать дополнительное **Действия**. Записать фактическую подпись (iOS может показывать Open) и необходимость Face ID. Само открытие не завершает задачу.
8. Отложить на 5 минут. Задача активна, прежний сигнал прекращается, новый один; исходный срок и Calendar event не перемещены. Повторить произвольное время.
9. Через **Действия** выбрать **Отключить будильник**: звук прекращается, будущих сигналов нет, задача активна. Перезапустить Nudge — будильник не восстанавливается. Включить позднее через строку/редактор и проверить отсутствие дублей.
10. Проверить отмену/ошибку: отказать AlarmKit permission, создать обычную задачу, затем включить сигнал. Задача не теряется, ошибка понятна. Если отмена сигнала при завершении не удалась, выполнение сохраняется; после восстановления доступа открыть Nudge и проверить завершение отмены.
11. Голосом произнести с паузами: «Напомни завтра в восемь вечера забрать посылку, а после этого позвонить маме». После Stop и финализации вся фраза сохраняется. Открыть **Исправить текст**; новая гипотеза не стирает уже введённую правку. Повторная запись очищает старую речь.
12. Произнести «Позвонить маме» без времени. **Создать** доступно для задачи без будильника. Включить будильник — появляется выбор будущего времени. Исправить название/дату, затем исходную фразу: корректные ручные поля не заменяются новой интерпретацией.
13. Быстро дважды нажать **Создать**, проверить ровно одну задачу. Повторить запуск из обоих виджетов, холодный запуск и повторное открытие: одна карточка записи, без второго аудиодвижка. Проверить микрофон после отмены, звонка и ухода в фон.
14. Проверить сохранение явно выбранного звука и индивидуального override. Без сохранённого предпочтения новые сигналы используют экспериментальный silent CAF. Проверить фактический звук/вибрацию; гарантия тишины не заявляется. Предупреждение/Preview находятся во вторичных параметрах/настройках.
15. Calendar: создать датированную задачу, изменить название и срок, выполнить, отключить будильник и Snooze. Событие не дублируется, переносится только при изменении срока, не удаляется при завершении/отключении. Без даты новая задача не получает искусственное событие; старое сохраняется при удалении срока.
16. Русский/английский, светлая/тёмная тема, крупный Dynamic Type и VoiceOver. Основные команды однозначны: Готово / Отложить / Отключить будильник / Изменить время / Создать.

## Минимальная модель и восстановление

- `scheduledAt: Date?` — необязательный исходный срок. Его имя и все старые идентификаторы сохранены. Добавлен только опциональный `alarmActionsVersion`.
- `completedAt` — выполнение. `alarmDisabled` — сохранённое намерение выключить сигнал. `alarmNeedsUpdate` у выполненной/выключенной задачи означает незавершённую отмену, не разрешение на новое планирование.
- Stop intent сохраняет выполнение до обращения к AlarmKit. Календарь не затрагивается. Если отмена/последующее сохранение прерваны, foreground reconciliation повторяет отмену. Результат завершения идемпотентен.
- Все async-планирования проверяют завершение/отключение после `await`; поздняя регистрация отменяется, включая неопределённую ошибку schedule(). Если эта отмена не удалась, сохраняется маркер восстановления.
- App и LiveActivityIntent переиспользуют один MainActor ModelContainer/mainContext с прежним default store. Нет нового пути, App Group, фонового polling или распределённой транзакционной системы.
- Старые реально зарегистрированные будущие сигналы обновляются с тем же ID/временем. После авторизации проверяется, что прежняя регистрация ещё существует: остановленный старый сигнал не восстанавливается. Записи с незавершённым Snooze/ошибкой не переписываются: сохраняется время явной повторной попытки.

SwiftData поддерживает [автоматические миграции](https://developer.apple.com/documentation/swiftdata/modelcontainer), а переход обязательного атрибута в опциональный входит в [lightweight migration Core Data](https://developer.apple.com/documentation/coredata/migrating-your-data-model-automatically). Это основание выбранной схемы, а не замена тесту обновления. Disk fixtures предыдущей 0.5.0/более ранних версий проверяют сохранность полей; новый disk test выполняет Stop через повторно открытые контейнеры.

## Ограничения AlarmKit

[AlarmConfiguration](https://developer.apple.com/documentation/alarmkit/alarmmanager/alarmconfiguration) принимает отдельные stopIntent/secondaryIntent. Код использует именно их; открытие действий не вызывает завершение. Поддерживаемые сигнатуры проверены по SDK 27.2, сохранённому CI.

- На iOS 26.1+ подпись Stop контролируется системой; приложение не пытается переименовать её через deprecated/неподдерживаемый API. Дополнительная кнопка может отображаться системой как Open.
- Foreground actions могут требовать разблокировки. Background LiveActivityIntent настроен alwaysAllowed, но реальный запуск при блокировке/выгруженном приложении и доступность защищённых данных, особенно до первого unlock после перезагрузки, требуют физической проверки. Обходов защиты нет.
- Аппаратные кнопки не переназначаются. Если они вызывают Stop intent, задача завершается по согласованной семантике.
- Уже звонящий сигнал старой конфигурации не переписывается: неизвестно безопасного способа заменить action без прерывания. После обновления сначала открыть Nudge; уже сработавший старый сигнал завершить из приложения.
- SwiftData и AlarmKit не атомарны. При отказе отмены возможен временно оставшийся системный сигнал; задача/намерение отмены сохранены, восстановление повторяется при открытии Nudge. Гарантия безусловного завершения при ошибках диска/системы не заявляется.

## Автоматическая проверка

Тесты охватывают задачи без даты/будильника, общий звук и сохранение явных настроек, durable/idempotent Stop, отдельный actions intent, включение без дублей, pending cancellation, гонки Stop/schedule и старой конфигурации, сохранность Calendar при Snooze, disk migration и полную транскрипцию. Реальные разрешения, сигналы и микрофон в unit-тестах не запускаются.

Локальные Command Line Tools не содержат SwiftDataMacros/ObservationMacros и современный iOS SDK. Доступны syntax/plist/catalog checks и Swift 6 проверки чистой логики с исключёнными UI/persistence macros. Полные iOS-сборки/тесты запускаются в GitHub Actions; их успех не доказывает физические сценарии выше.
